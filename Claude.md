# Claude Development Guide

## Project Overview

A minimal, local-first ML application that predicts developer salaries using Stack Overflow
Developer Survey data. Built with Python 3.12, XGBoost, Pydantic v2, and Streamlit. Emphasises
clarity and simplicity over production completeness.

One model is trained on the **2025 and 2026** surveys combined, with `SurveyYear` as a
categorical feature. The app predicts both years for the same input and shows the 2026
change vs 2025 (in %, USD and local currency). The implementation spec for this is
`PRD.md` (local only, gitignored).

### Training the model

```bash
uv run python -m src.train
```

Generates:

- `models/model.pkl` — trained XGBoost model
- `config/valid_categories.yaml` — valid input values for runtime guardrails
- `config/currency_rates.yaml` — 2025 per-country median currency conversion rates
- `config/currency_rates_2026.yaml` — 2026 per-country median currency conversion rates

### Hyperparameter tuning (optional, run before training)

```bash
make tune
# or
uv run python -m src.tune --n-trials 50
```

Reads search space from `config/optuna_config.yaml`, writes best parameters back into
`config/model_parameters.yaml`.

### Running the Streamlit app

```bash
uv run streamlit run app.py
```

### Running inference programmatically

```python
from src.schema import SalaryInput
from src.infer import predict_salary, predict_salaries, get_local_currency

input_data = SalaryInput(
    country="United States of America",
    years_code=5.0,
    work_exp=3.0,
    education_level="Bachelor's degree (B.A., B.S., B.Eng., etc.)",
    dev_type="Developer, full-stack",
    industry="Software Development",
    age="25-34 years old",
    ic_or_pm="Individual contributor",
    org_size="20 to 99 employees",
    employment="Employed",
)
salary = predict_salary(input_data)                    # 2025 (default)
salary_2026 = predict_salary(input_data, survey_year="2026")
both = predict_salaries(input_data)                    # {"2025": ..., "2026": ...}
local_2026 = get_local_currency(
    input_data.country, both["2026"], survey_year="2026"
)
```

Valid values for each categorical field are listed in `config/valid_categories.yaml`
(generated at training time).

## Data Requirements

One folder per survey year, file names kept exactly as in the Stack Overflow zip:

| Year | Path |
| ---- | ---- |
| 2025 | `data/2025/survey_results_public.csv` |
| 2026 | `data/2026/survey_results_public.csv` |

The year → path mapping lives in `config/model_parameters.yaml` under `data.sources`.
Column renames between years go in `data.column_renames` (2026: `Education` → `EdLevel`,
`Role` → `DevType`, `Compensation` → `CompTotal`). 2026 answer wording that differs from
2025 goes in `config/category_mapping_2026.yaml`, referenced from `data.category_mappings`
(e.g. 2026 `ICorPM` "senior/staff IC" → "Individual contributor", "Both" → "People
manager"; reworded `Industry` and `DevType` values). Output paths for per-year currency
rates are set in `data.currency_rates`.
`SurveyYear` (`"2025"` / `"2026"`, string) is added by the loader, not read from the CSV.

Each `survey_results_public.csv` must include these columns (plus `Currency` and
`CompTotal`, used for currency rates):

| Column | Description |
| ------ | ----------- |
| `Country` | Developer's country of residence |
| `YearsCode` | Total years coding (including education) |
| `WorkExp` | Years of professional work experience |
| `EdLevel` | Highest education level |
| `DevType` | Primary developer role |
| `Industry` | Industry the developer works in |
| `Age` | Age range |
| `ICorPM` | Individual contributor or people manager |
| `OrgSize` | Organisation size (number of employees) |
| `Employment` | Current employment status |
| `ConvertedCompYearly` | Annual salary in USD (target variable) |

## Input Validation (Two Layers)

### Layer 1 — Pydantic schema (`src/schema.py`)

All 10 fields are required. `years_code` and `work_exp` must be `>= 0`. Validated at
object construction time — raises `ValidationError` on failure.

### Layer 2 — Runtime guardrails (`src/infer.py`)

Each categorical field is checked against `config/valid_categories.yaml` at inference
time. Raises `ValueError` with a clear message on invalid input. The `survey_year`
argument is checked against `valid_categories["SurveyYear"]` in the same way.

## Key Files

### [src/schema.py](src/schema.py)

Pydantic v2 `SalaryInput` model — defines all 10 required input fields, types, and
constraints. The JSON schema example in the docstring is the canonical usage example.

### [src/preprocessing.py](src/preprocessing.py)

`prepare_features(df)` — takes a raw DataFrame and returns an encoded feature matrix:

- Unicode apostrophe normalisation on all categorical columns
- Rare category → "Other" normalisation
- Missing numeric values → 0
- Missing categoricals → "Unknown"
- One-hot encoding (training uses `drop_first=True`; inference uses `drop_first=False`
  then reindexes to match training columns)
- `SurveyYear` is a categorical column like the others; with `drop_first=True` the model
  sees a single `SurveyYear_2026` column (2025 is the all-zeros baseline)

### [src/train.py](src/train.py)

Full training pipeline:

1. `load_survey_data(config)` — read every year in `data.sources`, apply renames and
   category mapping, add `SurveyYear`, concatenate. Shared by `preprocess.py`, `tune.py`
   and `guardrail_evaluation.py` (no other script reads the CSVs directly)
2. Filter salaries (min/max percentile per `SurveyYear` + `Country`)
3. `apply_cardinality_reduction` — collapse rare categories to "Other" (on combined data)
4. `drop_other_rows` — remove rows with "Other" in specified columns
5. `prepare_features` — encode features
6. 5-fold CV with MAPE metric
7. Train final XGBoost model on full data with early stopping
8. Save `models/model.pkl`, `config/valid_categories.yaml`, and currency rates computed
   separately per year by `save_currency_rates`: `config/currency_rates.yaml` (2025
   rows) and `config/currency_rates_2026.yaml` (2026 rows). A country keeps the previous
   year's currency while it still appears in the data (Argentina stays ARS, Serbia RSD);
   otherwise the most common one is used (Bulgaria: BGN → EUR)

### [src/tune.py](src/tune.py)

Optuna study over the search space in `config/optuna_config.yaml`. Writes best
parameters back into `config/model_parameters.yaml` after the study completes.

### [src/infer.py](src/infer.py)

`predict_salary(SalaryInput, survey_year="2025")` — validates categories, builds a
single-row DataFrame, runs `prepare_features`, reindexes to training columns, returns
float USD salary. The `"2025"` default keeps older callers working.
`predict_salaries(SalaryInput)` — returns `{"2025": usd, "2026": usd}` by calling
`predict_salary` once per year in `valid_categories["SurveyYear"]`.
`get_local_currency(country, salary, survey_year="2025")` — converts to local currency
using that year's rates file. If a country has no rate for that year, it uses the other
year's rate.

### [app.py](app.py)

Streamlit UI with dropdowns populated from `config/valid_categories.yaml` (only values
that appeared in the training data). The user does not choose a year; one click shows
2025 and 2026 side by side, each in USD + local currency (each year uses its own rate).
2026 metrics carry an `st.metric` delta such as `+3.4% vs 2025`, for USD and for local
currency (the local % includes exchange-rate changes, so it can differ from the USD %).

## Updating Features

When adding a new input feature, update **all** of the following in order:

1. `config/model_parameters.yaml` — add to `features.cardinality.drop_other_from` if applicable
2. `src/schema.py` — add field to `SalaryInput`
3. `src/preprocessing.py` — add to `_categorical_cols` (or numeric handling)
4. `src/train.py` — add to `CATEGORICAL_FEATURES`
5. `guardrail_evaluation.py` — add to `CATEGORICAL_FEATURES` (CSV columns come from
   `load_survey_data`, so `tune.py` needs no change)
6. `src/train.py` — add to `REQUIRED_COLUMNS` (used by `load_survey_data` for all years;
   re-exported by `src/preprocess.py`)
7. `src/infer.py` — add validation block and DataFrame column
8. `app.py` — add selectbox, default, sidebar entry, `SalaryInput` construction
9. `tests/conftest.py` — add to `sample_salary_input` fixture
10. `tests/test_schema.py` — assert field, add missing-field test
11. `tests/test_infer.py` — add invalid-value test
12. `tests/test_feature_impact.py` — add to all `base_input` dicts, add impact test
13. `tests/test_preprocessing.py` — add column to all `pd.DataFrame(...)` fixtures
14. `tests/test_train.py` — add column to `_make_salary_df` and all test DataFrames
15. `README.md` — required columns, valid categories list, code example
16. `Claude.md` — data requirements table, field counts, code example, version
17. `example_inference.py` — add to all `SalaryInput` calls
18. Retrain: `uv run python -m src.train`

`SurveyYear` is a **derived** feature (added by the loader), not a user input: it is not
in `SalaryInput` and has no selectbox. It must **not** be added to `drop_other_from`.

### Adding a new survey year (e.g. 2027)

1. Put the CSVs in `data/<year>/` and add the year to `data.sources`
2. Check the schema: required columns present? answer wording changed? If so, add
   `data.column_renames` / `config/category_mapping_<year>.yaml`
3. Add `config/currency_rates_<year>.yaml` to `data.currency_rates` (written by
   `save_currency_rates`, loaded by `infer.py` automatically)
4. Nothing to change in `predict_salaries` / `app.py`: both loop over
   `valid_categories["SurveyYear"]`; deltas are shown vs the earliest year
5. Update tests, README, this file; retrain

## Versioning

Follows [Semantic Versioning](https://semver.org/):

- **MAJOR** — new required input field, incompatible model artifact, renamed API
- **MINOR** — new optional field, new supported country, new Makefile target
- **PATCH** — bug fix, model retrain with same schema, config tuning

Current version: `3.1.0` (added 2026 survey data, derived `SurveyYear` feature, dual-year
predictions; backward compatible API). Previous: `3.0.0` (added `Employment` required field).

Update `pyproject.toml` before tagging:

```bash
git tag v3.1.0
git push origin v3.1.0
```

## Troubleshooting

| Symptom | Fix |
| ------- | --- |
| `FileNotFoundError: model.pkl` | Run `uv run python -m src.train` |
| `FileNotFoundError: valid_categories.yaml` | Same — generated by training |
| `ValidationError` on `SalaryInput` | Check all 10 fields are present and non-negative numerics |
| `ValueError: Invalid ...` at inference | Value not in `config/valid_categories.yaml`; retrain or use a listed value |
| Data file not found for a year | Check `data.sources` paths and `data/<year>/survey_results_public.csv` |
| 2026 delta is ~0% for every input | Model barely splits on `SurveyYear`; check per-year row counts, consider `make tune` |
| Local currency missing for one year | Country has no rate in that year's file; the other year's rate is used |
| `E501` ruff errors | Lines > 79 chars — split strings, use variables, or wrap lists |
| Tests fail after adding a feature | Check the "Updating Features" checklist above |
